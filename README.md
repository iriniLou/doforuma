# Важное с собой

Игра перед II Всероссийским форумом молодых педагогов «Вместе о важном», 12–15 ноября 2026 года.

## Первая часть

Три предмета в чемодане, три главы, шесть сюжетных эпизодов, уточняющие вопросы, решения с последствиями и открытка в PNG. Предметы открывают дополнительные ходы, лупа даёт дополнительный вопрос. Предыдущие решения меняют продолжение и итог. Прогресс и необязательные заметки сохраняются в браузере; передачи ответов организаторам нет. Приблизительное время прохождения — 18–23 минуты; фактическое время пользовательского тестирования ещё не замерялось.

Оформление использует палитру приложенного брендбука «Разговоры о важном»: #FF553E, #63BAFF, #FF94CC, #93E479, #FFCC5B. Иллюстрация чемодана нарисована в SVG. Внешние шрифты, аналитика, рекламные скрипты и сетевые зависимости отсутствуют. Основной шрифт — системный Arial/sans-serif; фирменный PT Root UI не приложен к проекту.

## Открыть

Сайт статический, сборка для размещения не требуется:

```sh
cd /workspace/doforuma
python -m http.server 8000 --bind 127.0.0.1
```

Для пересылки одним файлом: `python build.py`, затем открыть `dist/Важное-с-собой.html` в браузере. Игра работает офлайн, раздел размещения требует сети и подключения API. Копия в одном файле использует отдельный локальный прогресс в зависимости от браузера.

## Размещение

Два входа доступны с главной. Поиск можно открыть после первого опроса и на любом этапе игры. После уточнения требований используются только ФИО, без почт. Реальных данных в репозитории нет.

Подключение Google-таблицы: [integration/README.md](integration/README.md). Сервер читает живой лист при каждом запросе, находит точную фамилию, возвращает варианты полных имён и соседей выбранного человека. При отсутствии подключения показывается сообщение о подготовке списка. Владелец развернул Apps Script и предоставил URL `/exec`; он подключён к обоим полям `config.js`. Прямая проверка настоящей таблицы из среды не выполнена: запрос блокируется прокси до обращения к Google. Существующие названия столбцов не менялись.

## GitHub Pages

В репозитории: Settings → Pages → Deploy from a branch → `main` → `/ (root)` → Save. После успешной публикации ожидаемый адрес: `https://irinilou.github.io/doforuma/`. Адрес считается опубликованным только после проверки ответа сайта.

## Правки

* `content.js` — предметы, ситуации, вопросы, варианты и последствия.
* `app.js` — переходы, сохранение, открытка и поиск.
* `visuals.js` — рисованные SVG вещей и шесть игровых ролей.
* `style.css` — адаптивное оформление и движение с учётом prefers-reduced-motion.
* `config.js` — URL сервера поиска и необязательная ссылка на контакт в MAX.

Тексты участников и данные заявок в код не копируются. Для уникальных тёзок сервер может показывать дополнительный согласованный признак (например, регион) после настройки `columns.detail`.

## Проверки

```sh
node --check app.js
node --check content.js
node tests/housing.test.cjs
# При работающем локальном сервере, установленных Playwright и Chromium:
python tests/e2e.py
```

Проверяются полное прохождение на компьютере и телефоне, бонусные ходы, ограничения вопросов, восстановление прогресса, экспорт PNG, замена предмета, выбор однофамильцев, обновление ответа API, ошибки сети и отсутствие данных размещения в localStorage. API в браузерном тесте подменён тестовыми ответами. Серверный тест использует вымышленные данные и имитацию Google Sheets.

## Обновление: карточки и статистика

В финале — одна из шести карточек по последовательности решений: «Архитектор общего дела», «Режиссёр первого шага», «Мастер плана Б», «Ловец тихих голосов», «Навигатор смысла», «Хранитель заряда». Роль определяется игровыми действиями, не случайно и не по выбранному затруднению. Это игровой результат, не профессиональная диагностика. Все роли достижимы с доступными наборами предметов.

Открытка на экране и PNG используют одну SVG-композицию. Полная карточка роли входит в открытку и скачивается вместе с ней одним PNG. Рисунки вещей встроены в SVG и не зависят от символов шрифта. Пояснения к предметам доступны по наведению и фокусу.

Анонимные счётчики запросов подготовлены в `integration/Code.gs`. До настройки `analyticsEndpoint` данные не отправляются. После подключения при нажатии «Продолжить» отправляется одна категория с коротким уведомлением об анонимном учёте; тексты заметок, открытки, ФИО и поиск размещения не отправляются. Инструкции — в integration/README.md.

Дополнительные проверки:

```sh
node tests/roles.test.cjs
node tests/analytics.test.cjs
python tests/review.py
```

## Вопросы до начала игры

На первом экране опроса добавлены два вопроса организатора: способ подготовки к последнему занятию (шесть готовых вариантов и свой ответ) и открытый вопрос экспертам. Вместе с выбранной нехваткой они отправляются по кнопке «Продолжить», до открытия игры и расселения. После подтверждённой записи завершать игру для сохранения ответов не требуется.

При сетевой ошибке ответы сохраняются в браузере; повтор использует тот же случайный технический ключ. Сервер записывает одну строку на этот ключ в отдельный лист «Ответы перед форумом», не меняя расселение и существующие заголовки. Ответ с открытым вопросом передаётся по явному запросу организатора; игровые заметки и текст открытки остаются локальными. Отправка не влияет на полученную игровую роль.

Предоставленный владельцем URL Apps Script подключён для анкеты и расселения. Режим просмотра выключен, требуется подтверждение записи от сервера. Фактическая запись в Google из среды не проверена из-за сетевой блокировки; перед рассылкой нужно проверить отправку с опубликованной страницы и появление строки в листе «Ответы перед форумом». В отдельном браузерном тесте `tests/configured-endpoint.py` проверены реальные значения конфигурации, подтверждение POST и поиск соседей с перехваченными тестовыми ответами; запросов на запись в настоящую таблицу тест не делает.

Проверки этой функции: `node tests/survey.test.cjs` и `python tests/survey-browser.py` (при работающем локальном сервере).

## Текущий порядок экранов

1. Опрос: три вопроса, без выбора предметов и доступа к размещению на этом экране.
2. После «Продолжить» — страница выбора игры или расселения.
3. При выборе игры — чемодан с тремя предметами, затем «В путь» и сюжет.

Участник с ранее сохранённым игровым прогрессом проходит новый опрос и может продолжить игру с прежнего места. Повторный запуск игры сохраняет уже отправленную анкету; повторная отправка для каждого прохождения не нужна. При появлении настроенного API локальный просмотр не считается серверной записью: требуется подтверждение от API.

## Формат расселения организатора

Одна строка содержит пару соседей в столбцах `Фамилия 1`, `Имя 1`, `Отчество 1`, `Регион 1`, `Фамилия 2`, `Имя 2`, `Отчество 2`, `Регион 2`. Обработчик разворачивает каждую строку в двух участников, ищет в обеих половинах и возвращает соседа из той же строки. Заголовки таблицы не меняются. Обновлённый `Code.gs` необходимо сохранить в Google Apps Script и выпустить новую версию существующего развертывания.

## Редакторские правки

Предпочтения организатора сохранены в TEXT_STYLE.md. К участнику обращаемся на «Вы». В подготовке есть «Свой вариант» с отдельным полем, в вопросе экспертам можно поставить прочерк. Для собственного ответа нужно обновить существующее развертывание Apps Script; таблица сохраняет прежние столбцы. Проверка: `python tests/editorial.py` и `node tests/survey.test.cjs`.

## Пересчёт игровых карточек и повторное прохождение

У каждого решения теперь указаны признаки роли в `choice.profile`. Роль считается по всем шести решениям: набранные баллы делятся на максимум для соответствующей роли, чтобы более частые категории не имели автоматического преимущества. При равенстве учитываются сильные совпадения и последние конкретные решения. Результат детерминированный; случайного выбора или выдачи роли по номеру кнопки нет. Незавершённая история карточку не получает. Замена вещей в финале результат не меняет.

Проверены все 29 835 доступных путей с наборами предметов. Доли ролей при равном переборе путей лежат примерно от 10 до 20%; это проверка перекоса алгоритма, а не распределение настоящих участников и не диагностика личности.

На финальном экране и рядом с готовой открыткой на главной есть «Пройти ещё раз». Повторное прохождение очищает игровые решения, заметки и открытку, сохраняя отправленную анкету. Браузерный тест `python tests/replay.py` проходит два разных пути подряд и проверяет разные роли без повторной отправки анкеты. Для этих изменений обновлять Apps Script не требуется.
