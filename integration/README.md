# Подключение листа «Расселение»

Игра работает без подключения таблицы. Пока URL сервера пустой в `config.js`, раздел размещения честно показывает «Список размещения готовится».

В этой версии используются **только ФИО**. Почты не запрашиваются, не показываются и не сохраняются. Игровой прогресс хранится локально, результаты поиска размещения — только в памяти страницы.

## Одна настройка владельцем таблицы

1. Откройте предоставленную Google-таблицу → Расширения → Apps Script.
2. Вставьте содержимое `Code.gs`. Проверьте название листа в `HOUSING.sheetName`.
3. Разверните новый **Web app**: выполнять от имени владельца, доступ — пользователям, у которых есть ссылка (пункт «Все», если доступен в вашей организации). Подтвердите чтение таблицы только для вашего скрипта. Публиковать саму таблицу в интернет не требуется.
4. Скопируйте URL развертывания, заканчивающийся `/exec`, в `housingEndpoint` файла `config.js`. Не используйте URL редактора или `/dev`.
5. Откройте сайт, найдите известную фамилию, выберите ФИО и сравните соседей с таблицей. Проверьте одинаковые фамилии, человека без соседей и изменение строки. Google Apps Script возвращает JSON с редиректом; перед массовой рассылкой проверьте запрос именно с адреса GitHub Pages.

Доступ к таблице и развёртывание требуют аккаунта её владельца; в этой сессии они не выполнялись. Структура таблицы пока не проверена из-за сетевого ограничения среды. Скрипт подготовлен под несколько вариантов заголовков, но реальное подключение необходимо проверить после получения доступа.

## Поддерживаемые столбцы

* Полное `ФИО` / `ФИО участника`, либо отдельные `Фамилия`, `Имя`, `Отчество`.
* `Комната` / `Номер` / `Номер комнаты` / `ID комнаты` / `Группа расселения` / `room_id` для группировки соседей. Номер должен быть заполнен в **каждой строке участника**, без объединённых ячеек. При наличии `Корпус`, `Гостиница` или `Отель` они включаются в ключ комнаты.
* Альтернатива комнате — `ФИО соседа` / `Соседка` / `Соседи` / `С кем живёт`. Несколько ФИО разделяются `;` или переносом строки. В этом варианте это готовые имена соседей из строки человека.
* Для нестандартных названий заполните `HOUSING.columns` точными названиями столбцов. Их порядок не важен. Посторонние столбцы игнорируются.
* Необязательные `ID` / `ID участника` поддерживаются. Дополнительный признак для различения полных тёзок можно задать через `columns.detail`, например `Регион`. По умолчанию ничего, кроме ФИО, не выдаётся.

Каждый запрос заново читает текущий лист: исправления и новые строки не требуют изменения сайта или повторного развёртывания скрипта. Изменение кода скрипта требует обновить версию развертывания. Если строка поменялась между поиском и выбором, повторите поиск.

## Контракт API

`GET /exec?surname=Иванова` → `{status:"matches",matches:[{id:"...",name:"Иванова Анна ..."}]}`.

`GET /exec?surname=Иванова&id=...` → `{status:"room",self:{name:"..."},roommates:[{name:"..."}],updatedAt:"..."}`.

Ошибка → `{error:"unavailable"}`. Клиент не показывает внутренние сведения таблицы.

Поиск по фамилии позволяет участнику запросить чужую фамилию. Это соответствует текущему сценарию поиска, но не является проверкой личности. Для ограничения доступа потребуется отдельная авторизация или персональная ссылка. В публичных файлах сайта полный список отсутствует.

## Анонимная статистика запросов

Тот же Apps Script поддерживает `doPost`: после развёртывания вставьте URL `/exec` также в `analyticsEndpoint` в `config.js`. Понадобится разрешение скрипту на запись в таблицу. Скрипт создаёт отдельный лист **«Статистика игры»**, где всего два столбца: категория затруднения и количество ответов.

Игрок может добровольно отметить согласие на анонимный учёт выбранного запроса. Отправка происходит при переходе «В путь»; игра доступна и без отметки. Сервер принимает только одну из пяти категорий и случайный ключ от повторов. Ключ живёт в серверном кэше до 6 часов, не записывается в таблицу и не связывается с размещением. В таблице нет строк отдельных пользователей, временных меток событий, ФИО, почт, заметок, текста открытки или результатов поиска размещения. Сам хостинг Google может вести технические журналы запросов; приложение IP-адреса не собирает.

Счётчик отражает количество полученных ответов, а не гарантированное число уникальных участников. До подключения `analyticsEndpoint` данные не отправляются. Реальная запись в Google Sheets в этой среде не проверена; локально проверены валидация, увеличение агрегата и защита от повторов на тестовых объектах.
